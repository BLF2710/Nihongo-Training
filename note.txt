Expanding the friend feature (options, not started)
---------------------------------------------------
How it works today: friend requests live in the friendships table (pending / accepted / declined, one row per
pair). Live updates use server-sent events at GET /api/events; the server only says "something changed" and
the page reloads through the normal API. Admins can switch Friends off under Manage content.
Ideas, roughly from small to large:
[ ] Block and report from a profile (blocking is only in Messages today) and a "blocked learners" list in settings
[ ] Friend suggestions: friends of friends, learners at the same level or unit (opt-in, never a public directory)
[ ] Activity feed: "Mika passed Unit 3", "Ren reached a 7-day streak" (needs an events table and per-item privacy)
[ ] Friend challenges: same kana or kanji round, compare scores; friend streaks (both study on the same day)
[ ] Nudges and cheers: one tap "keep your streak going" (rate-limited), reactions to achievements
[ ] Online / studying-now presence (from the live stream; must be optional)
[ ] Finer privacy: choose separately who sees level, streak, achievements, course progress
[ ] Profile pictures stored on our own server (outside image addresses are not shown, to avoid tracking)
[ ] Browser push or email digests for notifications (the notification centre and its history exist)
[ ] More notification kinds: friend milestones (streaks, units passed), admin broadcasts, per-kind mute settings
[ ] Scale the live stream past one API process: PostgreSQL LISTEN/NOTIFY or Redis pub/sub behind publish()
     in nihon-api/src/services/realtime.service.ts; behind a proxy, turn off response buffering for /api/events
[ ] Study groups / class codes later reuse the same pieces (membership table, live events, privacy rules)
